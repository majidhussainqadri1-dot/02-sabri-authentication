# File 02 / V12.3 P00 — Authorized Read-Only Live Reality Freeze

**Status:** Operator handoff prepared; **NOT EXECUTED on Hostinger**. Source candidate Draft PR #28 does not imply that the deployed plugin shares this code, schema or version.

## Purpose and strict safety boundary
Read only the deployed facts **before any live bug diagnosis or write**. A user-facing symptom, GitHub PR, ZIP or passing CI is not evidence of the live source. The operator must first obtain backup protection and site owner permission. The helper does **not** send HTTP requests, change DB, change plugin state, edit configuration, create users, read individual patient/user rows, or collect log contents. It deliberately excludes all secrets and private configuration option values.

### Inputs
- Authoritative WordPress installation path and SSH/WP-CLI access held by the authorized host operator, not by a public visitor.
- **A reviewed local copy** of `tools/file02-live-reality-freeze-readonly.php` from the exact approved source commit (never upload it into an untrusted web-accessible folder).
- Approval for CLI metadata reads and, separately, optionally expensive exact aggregate row counts. The base snapshot does **not** scan user records or count rows.
- Secure local storage for the output JSON; do not paste raw logs, passwords, medical content, keys or personal records into chat.

### Operator procedure (sample only, never run by ChatGPT from GitHub)

Do not execute if the CLI is not correctly pointed at the intended site; do not use this tool as a production monitoring hook or web endpoint. Inspect WordPress bootstrap behavior separately if the site may run side-effectful hooks on startup.
