## Contract A — Account Recovery Cooling-Off
Hook **required by existing File02 source**:
```php
apply_filters(
    'sauth_apply_recovery_change_v1',
    null,
    (string) $row['change_kind'],
    absint( $row['user_id'] ),
    $payload
);
```
- Only a *canonical, independently reviewed File00 owner* may install the callback. Keep unconfigured until accepted.
- A return value of strictly `true` is required by File02 to proceed from `processing` to `applied`. Any other result is unsuccessful; **the previously claimed case remains in `processing`** for supervised reconciliation, not automatic replay.
- Before invocation, File02 already requires: Safe Mode clear, exact pending state, valid UTC cooling-off time, valid encrypted proof, validated payload, collision type excluded, hook registered, and atomic `pending→processing` update.
- File00 must **independently reauthorize** actor, subject, guardian/role restrictions, current revocation/suspension, field transition, optimistic version and durable audit. No File02 token alone authorizes the target change.
- Owner must enforce idempotent business effect at File00 identity key/scope, handle uncertain processing and provide a safe operator readback/reconciliation path. Do not claim DB transaction atomicity across File00 and File02 unless a true shared transaction is proven.

## Contract B — Account Collision Resolution
Hook **required by existing File02 source**:
```php
apply_filters(
    'sauth_resolve_collision_case_v1',
    null,
    $payload,
    array(
        'case'        => $public_id,
        'fingerprint' => SA_Security::client_fingerprint(),
    )
);
```
- File02 rejects absent hook BEFORE consuming case; one-time fingerprint-bound proof expires after 600 seconds, and the verified case is claimed `pending→processing` before invoking File00.
- Owner success must return **array** `['result'=>'allow', 'user_id'=>positive_int]`, and File02 reassigns that canonical user ID to the case, then marks `applied`.
- An array/denial/error/malformed result does **not** authorize automatic retry or merge; after owner invocation the case remains processing until supervised outcome reconciliation.
- File00 must prove the correct account identity with non-email-only evidence, consent/guardian authorization, entitlement and canonical owner decision. A collision warning is not proof an old/new account can be merged.
- The `fingerprint` field is a bounded request signal, not an identity proof. The `case` must be bound to an authorized, audited File00 transaction with durable owner outcome and no sensitive payload in URLs.
