## Immutable inputs and boundaries

1. **Snapshot:** an authorized, private read-only JSON output from `tools/file02-live-reality-freeze-readonly.php` executed manually through WP-CLI against the exact site by its operator. The snapshot contains no user rows, secrets or logs. Never run a GitHub workflow against production to manufacture a snapshot.
2. **Package manifest:** the exact candidate CI `02-sabri-authentication-1.4.0-MANIFEST.json` accompanying the deterministic, archived ZIP from the SAME source HEAD. Record release artifact SHA-256 separately.
3. **Offline process:** copy only approved metadata into a private folder, then run Python without internet, writes or WordPress credentials:

```bash
python3 tools/file02-offline-deployment-parity.py \
  --snapshot /SECURE/reality-freeze.json \
  --manifest /SECURE/02-sabri-authentication-1.4.0-MANIFEST.json
```

This compares SHA-256 of the main plugin file, the sorted installed plugin tree, exact file count, plugin header version and plugin identity. It reconstructs the generated `PACKAGE-MANIFEST.json` file exactly from the immutable manifest schema. It refuses unsafe file paths, duplicate manifest paths, read errors, symlink-skipped incomplete trees and ambiguous simultaneous active File02 plugin folders.

**Result semantics:**

| `file_byte_parity` | Valid interpretation | Forbidden inference |
|---|---|---|
| `match` | The selected *active* File02 installed plugin source bytes match that exact release manifest | Does **not** prove DB schema, migration, PHP configuration, actual user journeys, staging, rollback or security-provider readiness |
| `mismatch` | The selected active source tree, runtime identity or main code digest differs | Do not apply a new code patch; first perform Deployment-Parity Audit |
| `unverified` | Missing/incomplete snapshot, invalid manifest, symlink/read error or ambiguous active path | Do not equate uncertainty with match or mismatch |

Exit codes: 0=byte match only; 1=mismatch/unverified; 2=invalid/unreadable input. Machine-readable output records `DB_version_verified=false`, `migration_verified=false` and `live_functional_verification=not_tested` in every case.
