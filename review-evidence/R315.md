# R315 — Passkey Runtime, Canonical Schema and Migration Review

Review baseline: `f8fbc8e4f9e98f0c1a7477373d14998fe5d5caf0`.

Method: WebAuthn/passkey parser, schema, hardened mutation runtime, credential migration, assurance handling and related tests were reviewed completely before any product correction. The defect ledger was then frozen and corrected as one batch, followed by cumulative regression.

Defects found:
1. Canonical passkey schema used `credential_lookup_hash` / `credential_id_ciphertext`, while active historical and hardened runtime paths still read/wrote `credential_hash` / `credential_cipher`.
2. Existing legacy credential rows had no pre-dbDelta migration into canonical columns.
3. Passkey environment readiness still proved only schema marker plus table existence rather than material canonical schema.
4. Registration count/duplicate DB read failures could collapse into safe-looking values and continue mutation.
5. Authentication credential lookup DB failure was indistinguishable from an unknown credential.
6. Signature-counter regression did not prove that credential quarantine and assurance invalidation succeeded.
7. Already-issued passkey ceremonies could finish after Safe Mode was raised.
8. The WebAuthn EC test fixture used OpenSSL coordinates without canonical 32-byte P-256 padding, producing a nondeterministic CI failure.

Corrections: canonicalized all active passkey physical-column use, added legacy credential-column preparation/copy verification before dbDelta, strengthened material readiness and fail-closed DB behavior, added Safe Mode finish gates and quarantine postconditions/containment, made the EC fixture deterministic, and added `tests/r315-passkey-canonical-schema-regression.php`.

Correction workflow run: `31810113447` — success. Product correction commit: `f3a0ae9ef0aace2789c02675f6a571c36a98bade`.
