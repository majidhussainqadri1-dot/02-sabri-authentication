# R314 — Google OIDC and Provider-Health Review

Review baseline: `db96e8a41e8dcbbd5d7648b662f4476f9df1d5dd`.

Method: Google OIDC/login/link/unlink, Google-first registration, HTTP provider guard, provider-health state machine, and existing Google regression coverage were reviewed completely before product correction. The defect ledger was then frozen and corrected as a batch.

Defect found: the interactive Google start paths called the mutating `allow_request('google')` health gate even though no server-to-server Google request occurs until the callback. In half-open state this consumed the single probe lease before the actual outbound HTTP request, blocking recovery and leaving the circuit unable to close normally. The Google-registration availability path had the same issue.

Correction: interactive availability is now non-mutating and makes cooled-down half-open flows visible; the actual outbound provider HTTP boundary remains the sole probe claimant and central success/failure observer. Added `tests/r314-google-provider-health-regression.php`.

Correction product commit: `271c81b04f316dbfd0ecfd1a3541ef22921bf5d5`.

Repository/source evidence only; not staging or live verification.
